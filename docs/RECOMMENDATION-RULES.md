# 등록과 추천 규칙

기준일 2026-10-08 · 앱 v25. 아래 수치는 실제 코드의 제품 정책이며 실측 보온·편안함이나 보편적인 색채 정답표가 아닙니다.

## 후보 생성

착용 가능한 보유옷만 사용합니다. (상의×하의 또는 원피스)×신발×(겉옷 없음 또는 보유 겉옷)의 조합을 순회합니다. 구매 후보·중복 ID·유효하지 않은 항목은 제외합니다. requiredId가 있으면 해당 옷을 반드시 포함합니다.

기본 순회 한도는 100,000개, 후보 보관은 160개, 최종 외부 추천은 최대 5개입니다. 큰 옷장으로 한도에 걸리면 모든 조합을 평가했다고 표시하지 않습니다. 일반 추천은 상하의 조합의 다양성도 고려합니다. ‘더 편하게’에서는 다양성 처리가 편안함 순서를 뒤집지 않습니다.

첫 추천은 상의1+하의1+신발1 또는 원피스1+신발1입니다. 다른 조합을 위해 예전의 상의2·하의2·신발1·겉옷1을 일괄 강제하지 않고 실제 유효 후보를 확인합니다.

## 날씨와 상황

기상청 저장 예보에서 활동 시간대를 사용합니다. 출근 기본 8/9/18/19시, 기타 10/12/15/18시, 저녁 약속은 20/21시 추가입니다. 정확한 개인 이동 시각을 측정한 값은 아닙니다. 관측 온습도가 없으면 예보와 구분하거나 미확인으로 둡니다.

기본 더위 경계는 23℃, 추위 경계는 12℃입니다. **하루 최고기온만으로 모든 패딩/울을, 최저기온만으로 모든 반팔/린넨을 일괄 제외하는 구현은 아닙니다.** 활동 시간 전체·보완 겉옷·확인된 보온/소재·민감도·습도를 함께 봅니다.

| 경우 | 현재 처리 |
| --- | --- |
| 더운 활동 시간, 추운 시간/냉방 보완 필요 없음 | 확인된 무거운 패딩·코트·울·기모 계열은 제외 조건 적용 |
| 아침 추위·냉방·큰 일교차 | 겉옷 필요성을 고려해 더위 경고/감점, 무조건 제거하지 않음 |
| 활동 내내 12℃ 이하 | 보완 없는 짧은 하의/반팔, 확인된 얇은 린넨 등 cold_light 조건 제외 |
| 보온 겉옷으로 반팔 보완 | 조건을 나누어 비교·안내 |
| 소재/날씨 모름 | 추측으로 확정 제외하지 않고 확인 필요 표시 |
| 필요한 겉옷이 없는 조합 | 감점과 부족 안내가 남을 수 있음. 모든 위험을 완전히 차단하는 의복 안전 판정은 아님 |

일반 출근은 neat-casual-office 정책입니다. 블랙 진·일반 운동화·일반 후드를 허용하고 슬리퍼와 명확한 운동복을 제외합니다. 구체적 세부 종류를 이름보다 우선하며, 넓은 분류는 이름 단서로 보완합니다. 재택·휴가와 격식 행사는 따로 판정합니다. 면접·결혼식·발표·중요 미팅·명시적 정장/격식 필수는 엄격한 조건을 유지합니다.

## 현재 색 점수

서버의 일반 추천 총점은 색+온도+격식+취향+최근 사용 항목으로 구성합니다. 의류의 선호 핏 일치 +2, 기존 스타일 선호 일치 +1, 느낌 연결 일치 +1 등을 옷별로 반영하며 최근 3개 선택에 등장한 옷은 개당 -0.3입니다. 도보 15분 이상에서는 신발의 확인된 편함/불편함도 참고합니다. 더 편하게는 이 총점보다 편안함을 먼저 정렬합니다.

색 점수의 대상은 상의·하의·원피스·겉옷입니다. 신발은 현재 색 점수에서 제외합니다.

| 판정 | 점수 |
| --- | --- |
| 확인된 수치로 선명한 유채색 옷 3개 이상, 보색 과다 조건 | -30 |
| 남색과 베이지가 함께 있고 허용된 중립색 범위 | +25 |
| 수치 기반 같은 색상 범위와 명도 차이 조건 | +25 |
| 전체 무채색 조합 | +20 |
| 위 규칙 없음/계열 정보만으로 미확정 | 0, 부족 정보는 별도 구분 |

주요 규칙 하나를 선택하며 가점을 무작정 합하지 않습니다. ‘무채색 하나만 포함하면 +20’, ‘데님은 모두 무채색’은 현재 코드가 아닙니다. 현재 같은 색상 판정은 첫 유효색 대비 색상각 20도 이내, 명도 차이 10 이상 등 기존 HSL 수치를 사용합니다. 보색 과다는 채도 65 이상인 유채색 3개 이상과 색상각 차이 150도 이상인 쌍을 포함하는 기존 규칙입니다.

새 설계의 OKLCH·유사색·톤인톤·대표 패턴 분배는 아직 미구현입니다. 색 이름만으로 정밀 수치를 만들지 않습니다.

## 두께 우선순위

보온값이 입력돼 있으면 기존 보온 목표 차이를 사용합니다. 없으면 두께 5단계(0 매우 얇음, 1 얇음, 2 보통, 3 두꺼움, 4 매우 두꺼움)를 비교합니다.

| 평가 기온 | 상의·하의·원피스 목표 | 겉옷 목표 |
| --- | --- | --- |
| 25℃ 이상 | 0~1 | 0~1 |
| 20℃ 이상 25℃ 미만 | 1~2 | 0~1 |
| 15℃ 이상 20℃ 미만 | 1~2 | 1~2 |
| 10℃ 이상 15℃ 미만 | 2~3 | 1~2 |
| 5℃ 이상 10℃ 미만 | 3~4 | 3~4 |
| 5℃ 미만 | 3~4 | 4 |

상의·하의는 활동 최고기온, 겉옷은 최저기온을 사용합니다. 더위 민감은 비교 기온 +2, 추위 민감은 -2입니다. 실내 난방은 안쪽 목표를 완화하고, 냉방이 있으면 따뜻한 때도 겉옷 목표를 보완합니다. 15℃ 미만에서 근거가 있는 AI 기모/충전 구조 단서는 두께를 잠정 한 단계만 보정합니다.

목표 범위에서 벗어난 단계당 4점 감점합니다. 두께 모름은 0점이나 ‘적합 확인’이 아닙니다. AI 두께만으로 새로운 강제 제외를 하지 않고, warmth에 덮어쓰거나 입력 보온과 중복 가산하지 않습니다.

## 더 편하게

현재 코디와 같은 역할 한 개만 바꾸며 편안함 점수가 반드시 개선돼야 합니다. 확인된 보온을 모름으로 낮추거나 날씨 목표 차이를 키우는 교체, 필요한 겉옷 제거, 걷기 조건 악화, 필수 복장 위반, 확인된 큰 색 충돌을 막습니다. 허용 후보는 편안함 점수 우선, 동률이면 기존 종합 점수로 비교합니다. 낮은 색 점수나 색 모름 자체를 탈락 이유로 삼지 않습니다.

| 임시 종류 점수 예 | 값 |
| --- | --- |
| 상의 후드/맨투맨, 티셔츠, 니트, 셔츠 | 4, 2, 1, 0 |
| 하의 조거/스웨트, 카고/치노, 데님, 일반 팬츠/슬랙스 | 4, 2, 1, 0 |
| 원피스 니트/티셔츠/스웨트형 | 2 |
| 겉옷 후드/집업/가디건/바람막이, 데님/카라/블루종 | 3, 1 |
| 신발 운동화/러닝화, 스니커즈, 단화, 하이힐 계열 | 4, 3, 1, -2 |

여유핏 +3, 밀착핏 -1, 관련 스타일 +0.5, 직접 편함 +2, 직접 불편함 -10을 참고합니다. 신발은 의류 핏 점수를 받지 않습니다. 원피스는 두 역할로 계산하지만 교체는 원피스끼리 한 번입니다. 출근 필터를 통과하지 못한 운동복은 편안함 점수가 높아도 후보가 아닙니다. 종류 점수는 실제 신축성·쿠션 측정이 아닙니다.

블랙 팬츠를 이름/검정색만으로 데님으로 만들지 않습니다. 후드 패딩은 가벼운 후드 아우터보다 먼저 구분합니다. 실제 바람막이 성능은 종류 이름만으로 보장하지 않습니다.

## Gemini와 후속 설계

최초 일반 추천에만 Top 5 텍스트를 전달하고 후보 ID·팁을 검증합니다. 더 편하게/더 단정하게/다른 조합은 추가 Gemini 호출 없이 처리합니다. AI가 새 옷이나 점수를 만들어 필수조건을 뒤집을 수 없습니다.

후속 색 공간 개편은 현재 구현 범위에 포함하지 않습니다.
