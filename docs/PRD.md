# ClosetAgent 제품 요구사항

기준일 2026-10-08 · 앱 v24.

보유한 옷으로 날씨와 일정에 맞는 옷차림을 추천합니다. 옷을 많이 등록하거나 매일 설문에 답해야만 시작할 수 있는 방식은 피합니다. 사용자가 수정한 정보와 모르는 항목을 존중합니다.

## 해결할 문제

실제 옷장에는 블랙 진과 바람막이가 있는데 등록명은 각각 ‘블랙 팬츠’, ‘블랙 후드 긴소매 재킷’이었습니다. ‘더 편하게’에서 슬랙스가 유지되고 얇은 패딩이 선택된 사례를 개선합니다. 이름만으로 청바지·방풍 기능을 확정하지 않고, 세부 종류와 확인된 속성을 추천까지 전달해야 합니다.

## 확정된 추천 원칙

1. 날씨·상황의 필수조건을 먼저 지킵니다.
2. 일반 출근은 깔끔한 캐주얼을 허용합니다. 블랙 진·운동화가 가능하며 슬랙스를 강제하지 않습니다. 슬리퍼와 명확한 운동복은 제외합니다.
3. 면접·결혼식·중요 미팅·정장 필수 일정은 별도의 격식 조건을 유지합니다.
4. ‘더 편하게’는 큰 색 충돌이 없는 후보 중 편안함을 우선합니다. 색 점수가 조금 높다는 이유로 덜 편한 후보를 먼저 고르지 않습니다.
5. 한 번 누를 때 같은 역할의 옷 하나만 교체하고, 다시 누르면 바뀐 코디를 기준으로 비교합니다.
6. 모르는 속성은 모름으로 남깁니다. AI 두께 추정은 사용할 수 있지만 실제 보온 성능이나 사용자 확인으로 승격하지 않습니다.

## 현재 구현 범위

| 기능 | 결과 |
| --- | --- |
| 생활 설정 | 3단계 초기 질문, 복수 활동지역·민감도·느낌 선택, 재편집 |
| 옷 등록 | 원본 사진 분석, 확인·수정, 선택적 배경 제거, 여러 장 순차 등록 |
| 속성 | 종류·색·핏·23스타일, 선택적 보온·소재·길이·색 수치, 두께 5단계와 출처 |
| 추천 | 서버에서 보유옷 조합 생성→필수조건 검사→색·기온·취향 계산→상위 후보 추출 |
| Gemini | 최초 일반 추천의 상위 최대 5개에 한해 텍스트 전달·팁/순서 보완. 조정 버튼은 추가 호출하지 않음 |
| 화면 | 사용자/개발자 표시 전환, 후보 부족·실패·재시도·오래된 응답 차단 |
| 데이터 | 브라우저 저장, Supabase 메타데이터 어댑터와 수동 동기화 화면 준비 |
| 기록 | 착용 선택, 선택적 피드백, 날씨·공휴일 저장본 활용, 비용 제한 |

추천 실패 시 브라우저 대체 계산이 있습니다. 서버와 필수조건·출근·편안함 정책을 공유하지만 전체 점수와 순서까지 완전히 동일하다고 보장하지 않습니다. 후보가 없으면 부적합 조합을 정상 추천처럼 만들어내지 않습니다.

## 완료 판단

구현 검사는 v24의 324개 자동 검사 통과가 근거입니다. 실제 개인 옷장의 두 사례 해결, 휴대폰 촬영, 새 두께 분석의 실제 정확도, 실제 로그인·사진 API의 원격 접근 차단, Vercel 운영은 별도 검증 대상입니다. DB 자체의 소유권 검사는 통과했습니다. 추천 점수는 제품 규칙이며 과학적 색 조화·착용감·보온 측정값이 아닙니다.

## 다음 출시 범위

GitHub에는 코드·공개 참고 데이터·문서·테스트를 보관합니다. Supabase에는 사용자별 정보와 비공개 사진을, Vercel에는 화면과 요청 처리 코드를 배포합니다. [데이터 설계](DATA.md)와 [배포 설계](DEPLOYMENT.md)에 따라 로컬 파일 의존·사진 전송·날씨 예약 실행·공동 예산을 바꿉니다.

누끼 룩북, 달력 연동, 매일 강제 질문, 쇼핑몰 자동 수집, 체형·사이즈 적합성 추정은 이번 범위에 넣지 않습니다. 기존 선택적 배경 제거와 일반 옷 이미지 표시는 유지 대상입니다.

색 3양식과 다층 보온 체계는 후속 설계입니다. 두께 구현을 이유로 해당 설계 전체가 완료됐다고 표시하지 않습니다.
