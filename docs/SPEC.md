# ClosetAgent 기능 명세

기준일 2026-10-08 · 앱 v24. 아래 F 항목은 로컬 소스에 구현된 기능입니다. 원격 서비스 검증 상태는 마지막 절과 [검증 문서](TESTING.md)을 따릅니다.

## 기존 기능

| --- | --- | --- |
| F01 | 최초 설정 | 실제 옷장·완료 기록이 없는 경우 생활→환경→취향 3단계. 작성 중 값 보존, 최종 저장 성공 후 완료 |

| F03 | 당일 일정 | 자유문장의 활동 단서를 기존 생활에 결합. 실제 달력/정확한 이동 경로 자동 수집 없음 |
| F04 | 기상청 예보 | 활동지역 저장본을 사용. 발표+15분 사전 수집, 신선도 표시. 서버가 꺼지면 수집 중단 |
| F05 | 날씨 안내 | 활동 시간대 기온, 비·눈·냉방·일교차 고려. 미확인 날씨를 실측으로 표시하지 않음 |

## 추천 API 계약

요청에는 requestId, wardrobeRevision, wardrobe 배열, profile, context, options를 전달합니다. 클라우드 모드에서도 요청 배열의 ID로 본인 옷을 다시 조회합니다. 별도 garmentIds만 보내는 공개 요청 형식은 아닙니다. options는 modifier, skip, history, requiredId, referenceIds, topK를 포함합니다. 외부 API의 topK는 최대 5이며 내부 순수 계산 함수의 상한과 구분합니다.

응답은 looks의 candidateId·itemIds·stylingTip·scores·이유와 diagnostics를 제공합니다. candidateId는 옷 ID 조합에서 생성합니다. 화면은 itemIds를 현재 옷장과 대조하며 옷장 수정·모드 전환 뒤 도착한 이전 응답을 적용하지 않습니다. 키·인증 토큰은 진단 정보에 포함하지 않습니다.

Supabase 모드에서는 서버가 사용자 토큰을 인증하고 등록된 본인 옷을 다시 읽습니다. 요청에 포함한 user_id나 점수를 신뢰하지 않습니다. 로컬 시험 모드와 공개 운영 모드를 섞지 않습니다.

## 아직 구현되지 않은 배포 변경

원격 사진 Storage, 생활/피드백 동기화, 변경 충돌 관리, 500개 초과 페이지 조회, Vercel 요청 처리 어댑터, 공유 예산 DB 연결, 예약 수집은 [DB 설계](DATA.md)와 [이전 계획](DATA-IMPORT.md)의 예정 사항입니다. DB 18개 표와 비공개 버킷, 권한 및 예산 함수는 적용됐고 SQL 검사 32개를 통과했습니다. 앱의 전체 동기화·사진 API·공유 예산 연결은 아직 미구현입니다.
