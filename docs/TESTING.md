# 검증 방법과 범위

## 이번 정리본 확인 결과

2026-10-08 기준 앱 324개, DB 32개 검사를 통과했습니다. 임시 검증 폴더에서 기존 설치 의존성을 연결해 검사했으며 새로운 환경에서 npm ci를 처음부터 실행하는 검사는 별도입니다. 서버를 별도 포트로 실행해 v24 화면, 추천 API 성공, Gemini 미호출, .env 접근 404를 확인했습니다.

업로드 후보는 110개 파일이며 그중 문서는 10개입니다. 내부 문서 링크 21개, 제외 규칙 사례 8개를 확인했습니다. 포함된 무시 대상 파일과 비밀 인증값의 주요 패턴 검출은 0개입니다. 검사 결과 파일·로그·설치 패키지는 업로드 후보에 넣지 않았습니다.

## 앱 검사

프로젝트 최상위에서 npm ci 후 npm test를 실행합니다. backend-network-guard.mjs를 먼저 불러와 외부 요청을 차단하고, 외부 공급자 응답은 가짜 응답으로 검사합니다. Gemini를 실제 호출하지 않습니다.

검사 대상은 추천 필수조건·색·편안함·두께, 사진 분석 응답 검증, 저장 복구, 서버/화면 연결, 옷장 소유권 어댑터 등입니다. fixtures는 합성 사진·추천 응답입니다. frontend-fixture-server.mjs는 자동 검사에서 사용하는 도구이므로 포함했습니다.

## DB 검사

터미널에서 database 폴더로 이동한 다음 npm ci, npm test를 실행합니다. PGlite 0.5.8로 격리된 로컬 PostgreSQL을 만들고 실제 적용된 두 SQL 변경 파일을 순서대로 실행합니다. 32개 검사는 본인/타인/익명 접근, 수정 충돌, 사진 메타데이터 권한, 예산 중복·한도 등을 확인합니다. 실제 계정이나 사진은 업로드하지 않습니다. 생성되는 local-verification.json은 Git 업로드에서 제외합니다.

원격 DB에도 같은 SQL 검증을 시행했고 시험 자료는 되돌렸습니다. 이것은 SQL 역할 기반 검사이며 실제 로그인·파일 업로드 API의 종단 검사를 대신하지 않습니다. 이미 적용된 프로젝트에 migration SQL을 다시 수동 실행하지 않습니다.

## 아직 확인할 항목

실제 블랙 진/바람막이 사례의 체감 품질, 실제 Gemini 두께 추정 정확도, 실제 기종의 촬영·배경 제거, 두 계정의 실제 로그인·사진 접근, 완전한 데이터 이전, Vercel 운영은 별도 검증이 필요합니다.
